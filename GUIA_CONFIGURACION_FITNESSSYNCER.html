🏃‍♂️ Configuración FitnessSyncer API

Guía completa para integrar datos de fitness en HealthPredict

¿Qué es FitnessSyncer?
FitnessSyncer es una plataforma que conecta con más de 100 aplicaciones de fitness (Mi Fitness, Google Fit, Samsung Health, Apple Health, Strava, etc.) permitiendo sincronizar todos los datos de salud en un solo lugar.
1 Ejecutar Migración de Base de Datos

Primero necesitas crear la tabla para almacenar las configuraciones de FitnessSyncer.

Importante: Detén tu aplicación HealthPredict antes de ejecutar la migración para evitar conflictos de archivos.

Opción A: Script SQL Directo

-- Conectar a PostgreSQL y ejecutar: psql -h ep-royal-dream-a4izfmtv-pooler.us-east-1.aws.neon.tech -d neondb -U neondb_owner -f MIGRACION_SIMPLE_FITNESSSYNCER.sql

Opción B: Entity Framework (Cuando la app no esté corriendo)

dotnet ef migrations add AddFitnessSyncerIntegration --project HealthPredict.DAL --startup-project HealthPredict.API dotnet ef database update --project HealthPredict.DAL --startup-project HealthPredict.API
Después de ejecutar, deberías ver la tabla FITNESS_SYNCER_CONFIGS en tu base de datos.
2 Registrarse en FitnessSyncer

Necesitas crear una cuenta de desarrollador en FitnessSyncer para obtener las credenciales de API.

🔗 Ir a FitnessSyncer Developers

Pasos en FitnessSyncer:

  • Crear cuenta de desarrollador
  • Crear nueva aplicación
  • Configurar Redirect URI: https://tu-dominio.com/api/fitnesssyncer/auth/callback
  • Obtener Client ID y Client Secret
  • Configurar permisos: sources, read
Redirect URI para desarrollo local:
http://localhost:5000/api/fitnesssyncer/auth/callback
https://localhost:5001/api/fitnesssyncer/auth/callback
3 Configurar appsettings.json

Agrega las credenciales de FitnessSyncer a tu archivo de configuración.

HealthPredict.API/appsettings.json

{ "ConnectionStrings": { "PostgreSQLConnection": "tu-connection-string" }, "FitnessSyncer": { "ClientId": "TU_CLIENT_ID_AQUI", "ClientSecret": "TU_CLIENT_SECRET_AQUI", "BaseUrl": "https://api.fitnesssyncer.com/api", "AuthUrl": "https://www.fitnesssyncer.com/api/oauth" }, "Logging": { "LogLevel": { "Default": "Information" } } }

Para Producción (appsettings.Production.json)

{ "FitnessSyncer": { "ClientId": "TU_CLIENT_ID_PRODUCCION", "ClientSecret": "TU_CLIENT_SECRET_PRODUCCION", "BaseUrl": "https://api.fitnesssyncer.com/api", "AuthUrl": "https://www.fitnesssyncer.com/api/oauth" } }
Seguridad: Nunca subas las credenciales reales al control de versiones. Usa variables de entorno en producción.
4 Probar la Aplicación

Reinicia tu aplicación y prueba los nuevos endpoints de FitnessSyncer.

cd HealthPredict.API dotnet run
Si todo está bien configurado, deberías ver la aplicación iniciarse sin errores y los nuevos endpoints disponibles en /swagger
5 Endpoints Disponibles

Una vez configurado, tendrás acceso a estos endpoints:

GET /api/fitnesssyncer/auth/url

Obtiene la URL de autorización OAuth para conectar con FitnessSyncer

GET /api/fitnesssyncer/auth/callback

Callback automático de OAuth (manejado por FitnessSyncer)

GET /api/fitnesssyncer/status

Verifica si el usuario está conectado a FitnessSyncer

POST /api/fitnesssyncer/sync

Sincroniza datos de fitness del usuario

GET /api/fitnesssyncer/stats

Obtiene estadísticas de sincronización

POST /api/fitnesssyncer/disconnect

Desconecta al usuario de FitnessSyncer

6 Prueba de Conexión

Realiza una prueba completa del flujo de autenticación.

Usando Postman o curl:

# 1. Obtener URL de autorización curl -X GET "https://tu-api.com/api/fitnesssyncer/auth/url" \ -H "Authorization: Bearer TU_JWT_TOKEN" # 2. Verificar estado de conexión curl -X GET "https://tu-api.com/api/fitnesssyncer/status" \ -H "Authorization: Bearer TU_JWT_TOKEN" # 3. Sincronizar datos (después de conectar) curl -X POST "https://tu-api.com/api/fitnesssyncer/sync" \ -H "Authorization: Bearer TU_JWT_TOKEN" \ -H "Content-Type: application/json" \ -d '{ "maxItemsPerSync": 50, "daysToSync": 7, "syncActivity": true, "syncWeight": true }'

Flujo de Usuario Frontend:

// JavaScript/TypeScript para Angular async conectarFitnessSyncer() { try { // 1. Obtener URL de autorización const response = await fetch('/api/fitnesssyncer/auth/url', { headers: { 'Authorization': `Bearer ${this.authToken}` } }); const { authUrl } = await response.json(); // 2. Redirigir al usuario a FitnessSyncer window.location.href = authUrl; } catch (error) { console.error('Error conectando con FitnessSyncer:', error); } } async sincronizarDatos() { try { const response = await fetch('/api/fitnesssyncer/sync', { method: 'POST', headers: { 'Authorization': `Bearer ${this.authToken}`, 'Content-Type': 'application/json' }, body: JSON.stringify({ maxItemsPerSync: 100, daysToSync: 30, syncActivity: true, syncWeight: true, syncBloodPressure: true }) }); const result = await response.json(); console.log(`Sincronizados ${result.result.newItems} nuevos elementos`); } catch (error) { console.error('Error sincronizando datos:', error); } }

8 Solución de Problemas

Problemas Comunes y Soluciones:

Error: "Build failed"
Solución: Detén la aplicación que está corriendo antes de compilar.
Error: "Table already exists"
Solución: La tabla ya fue creada. Continúa con la configuración.
Error: "Client ID not found"
Solución: Verifica que las credenciales estén correctas en appsettings.json
Error: "Invalid redirect URI"
Solución: Verifica que el redirect URI en FitnessSyncer coincida exactamente con tu dominio.

Logs Útiles:

# Ver logs de la aplicación dotnet run --verbosity detailed # Ver logs específicos de FitnessSyncer # (Los verás en la consola cuando uses los endpoints)
